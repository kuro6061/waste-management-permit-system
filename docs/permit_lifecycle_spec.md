# 許可・施設ライフサイクル仕様書

**バージョン**: 1.0
**作成日**: 2026-02-28

---

## 1. 概要

本システムは廃棄物処理業の許可情報を管理する。許可と施設には「履歴追跡」機能があり、
同一エンティティの過去の状態を任意の時点で参照できる。

この仕様書では、履歴追跡の設計意図と、各ライフサイクルイベントにおける
データベース操作の詳細を定める。

---

## 2. 法的根拠

### 2.1 業許可（廃棄物処理法 第14条）

| 条項 | 内容 |
|------|------|
| 14条1項 | 産業廃棄物の収集運搬・処分を業として行うには都道府県知事の許可が必要 |
| 14条2項 | 許可は**5年を下らない期間**ごとに更新が必要（更新しなければ失効） |
| 14条3項 | 更新申請が提出済みで、有効期間満了日までに処分がされないときは、**従前の許可はなお効力を有する**（みなし有効） |
| 14条4項 | 更新された場合、新許可の有効期間は**従前の許可の有効期間満了日の翌日から起算** |

### 2.2 施設許可

施設の許可（設置許可）は有効期間の定めがなく、**廃止するまで有効**。

### 2.3 許可の終了事由

| 事由 | 条文 | 性質 |
|------|------|------|
| 更新（期間満了） | 14条2項 | 更新申請→新許可発行で継続 |
| 取消 | 14条の3の2 | 行政処分（都道府県知事が強制的に取消す） |
| 廃止 | 14条の2第4項 | 事業者の自主的な事業廃止 |

## 3. データモデル: 2種類の日付

### 3.1 業務日付（許可証に記載される日付）

| カラム | 意味 | 例 |
|--------|------|-----|
| 許可年月日 | 許可が下りた日（許可証の発行日） | 2025/05/15 |
| 許可有効年月日 | 許可証に記載された有効期限 | 2030/03/31 |
| 廃止日 | 事業者が自主的に廃止した日 | - |
| 取消日 | 行政処分による取消日 | - |

これらは許可証という「紙の書類」に対応する事実の記録であり、
一度登録されたら原則変更しない。

### 3.2 システム日付（レコード版管理用）

| カラム | 意味 | 例 |
|--------|------|-----|
| 有効開始日時 | このレコードが「最新版」になった日 | 2025/05/15 |
| 有効終了日時 | このレコードが「最新版」でなくなった日。NULL=現在の最新版 | 2025/05/14 |
| 作成日時 | レコードがDBに挿入された日時 | 2025/05/15 |

これらはシステム内部でどのレコードが「現在の最新版か」を管理するための日付であり、
許可証の有効期間とは別の概念。

### 3.3 なぜ2種類の日付が必要か

廃棄物処理法14条3項（みなし有効）により、以下の状況が発生する:

```
旧許可: 許可年月日=2020/04/01, 許可有効年月日=2025/03/31
更新申請: 2025/02/15（期限前に提出）
新許可: 2025/05/15（処分=許可決定の日）

■ 許可証上の日付:
  旧許可証: 有効期間 2020/04/01～2025/03/31
  新許可証: 有効期間 2025/05/15～2030/03/31
  → 許可証だけ見ると 2025/04/01～2025/05/14 に「空白」がある

■ 法律上の効力:
  2020/04/01 ～ 2025/05/14  旧許可が有効（14条3項: みなし延長）
  2025/05/15 ～ 2030/03/31  新許可が有効（14条4項: 旧満了日翌日から起算）
  → 法律上は隙間なく連続

■ システム上のレコード管理:
  旧レコード: 有効開始日時=2020/04/01, 有効終了日時=2025/05/14
  新レコード: 有効開始日時=2025/05/15, 有効終了日時=NULL
  → 任意の日付で「その時点の最新レコード」を特定できる
```

許可証の業務日付だけでは「2025/04/01時点でこの事業者は許可を持っているか？」
という検索に対応できない。システム日付により、みなし有効期間中も
旧許可レコードが「最新版」として正しくヒットする。

## 4. 許可論理ID と 許可ID

| カラム | 役割 | 例 |
|--------|------|-----|
| 許可ID | 物理ID。レコードごとにユニーク（AUTOINCREMENT） | 1, 2, 3, ... |
| 許可論理ID | 論理ID。同一許可の全バージョンで共通 | 同じ許可なら全レコードが同じ値 |

```
許可ID=1: 許可論理ID=100, 有効開始日時=2020/04/01, 有効終了日時=2025/05/14  ← 旧版
許可ID=2: 許可論理ID=100, 有効開始日時=2025/05/15, 有効終了日時=NULL        ← 現行版
```

- 新規許可の登録: 新しい許可論理IDを採番（MAX+1）
- 許可の更新: 同じ許可論理IDで新レコードをINSERT

## 5. ライフサイクルイベント詳細

### 5.1 業許可: 新規登録

事業者が初めて許可を取得した場合。

**操作:**
- 新しい許可論理ID を採番（MAX+1）
- 許可テーブルにINSERT

**DB変更:**
```
INSERT INTO 許可 (
    許可論理ID, 事業者ID, 許可区分ID, 許可番号,
    許可年月日, 許可有効年月日, 優良認定,
    有効開始日時, 作成日時
) VALUES (
    [新規論理ID], [事業者ID], [区分ID], [番号],
    #許可年月日#, #許可有効年月日#, [True/False],
    #今日#, #今日#
)
```

| カラム | 値 |
|--------|-----|
| 有効開始日時 | 登録日（今日） |
| 有効終了日時 | NULL（現在有効） |
| 廃止日 | NULL |
| 取消日 | NULL |

### 5.2 業許可: 更新（14条2項）

既存許可の有効期間が満了し、新しい許可が発行された場合。
**同一の許可論理IDを使用する。**

**操作（2ステップ）:**
1. 旧レコードの有効終了日時を設定（新許可の前日）
2. 同じ許可論理IDで新レコードをINSERT

**DB変更:**
```
-- Step 1: 旧レコードを閉じる
UPDATE 許可
SET 有効終了日時 = #新許可の許可年月日の前日#
WHERE 許可ID = [旧レコードの許可ID]

-- Step 2: 新レコードを作成
INSERT INTO 許可 (
    許可論理ID, 事業者ID, 許可区分ID, 許可番号,
    許可年月日, 許可有効年月日, 優良認定,
    有効開始日時, 作成日時
) VALUES (
    [同じ論理ID], [事業者ID], [区分ID], [番号],
    #新許可年月日#, #新許可有効年月日#, [True/False],
    #新許可の許可年月日#, #今日#
)
```

**日付の設定ルール:**
| 項目 | 旧レコード | 新レコード |
|------|-----------|-----------|
| 有効開始日時 | 変更なし | 新許可の許可年月日 |
| 有効終了日時 | **新許可の許可年月日の前日** | NULL |
| 許可年月日 | 変更なし | 新許可証に記載の日付 |
| 許可有効年月日 | 変更なし | 旧許可有効年月日 + 5年 |

**重要:** 旧レコードの有効終了日時は「新許可の許可年月日の前日」。
新レコードの有効開始日時は「新許可の許可年月日」。重複なく連続する。

### 5.3 業許可: 廃止（14条の2第4項）

事業者が自主的に事業を廃止した場合。

**操作:**
- 廃止日、廃止理由、有効終了日時を設定

**DB変更:**
```
UPDATE 許可
SET 廃止日 = #廃止日#, 有効終了日時 = #廃止日#, 廃止理由 = '理由'
WHERE 許可ID = [対象の許可ID]
```

| カラム | 値 |
|--------|-----|
| 廃止日 | 廃止した日付 |
| 廃止理由 | 任意テキスト |
| 有効終了日時 | **廃止日と同じ日付を設定** |

**有効終了日時を設定する理由:**
- 年度末時点等のas-of検索で、廃止済み許可を正しく除外するため
- 施設の廃止と同じ挙動に統一

**補足:**
- 廃止された許可論理IDで、新しいレコードが作られることはない
  （再度事業を行う場合は新規申請→新しい許可論理ID）

### 5.4 業許可: 取消（14条の3の2）

行政処分により許可が取消された場合。

**操作:**
- 取消日、取消理由、有効終了日時を設定

**DB変更:**
```
UPDATE 許可
SET 取消日 = #取消日#, 有効終了日時 = #取消日#, 取消理由 = '理由'
WHERE 許可ID = [対象の許可ID]
```

| カラム | 値 |
|--------|-----|
| 取消日 | 取消処分の日付 |
| 取消理由 | 任意テキスト |
| 有効終了日時 | **取消日と同じ日付を設定** |

**理由は廃止と同じ。** 取消後に同じ論理IDで新許可が出ることはない。

### 5.5 業許可: 復活（廃止・取消の取り消し）

誤って廃止・取消した場合の復元操作。

**DB変更:**
```
UPDATE 許可
SET 廃止日 = NULL, 廃止理由 = NULL,
    取消日 = NULL, 取消理由 = NULL,
    有効終了日時 = NULL
WHERE 許可ID = [対象の許可ID]
```

有効終了日時もNULLに戻し、「現在有効な最新版」として復元する。

### 5.5 施設: 新規登録

**操作:**
- 新しい施設論理IDを採番
- 施設テーブルにINSERT

**DB変更:**
```
INSERT INTO 施設 (
    施設論理ID, 事業者ID, 施設種別ID, 設置場所,
    許可番号, 許可年月日, 設置年月日, 有効開始日時
) VALUES (
    [新規論理ID], [事業者ID], [種別ID], '場所',
    '番号', #許可年月日#, #設置年月日#, #今日#
)
```

### 5.6 施設: 廃止

施設の廃止。施設許可には有効期間の定めがないため、「更新」の概念はない。

**DB変更:**
```
UPDATE 施設
SET 有効終了日時 = #廃止日#, 廃止年月日 = #廃止日#
WHERE 施設ID = [対象の施設ID]
```

業許可の廃止と同様、有効終了日時を設定することでas-of検索から正しく除外される。
廃止された施設論理IDで新しいレコードが作られることはない。

## 6. 検索における有効開始日時/有効終了日時の使い方

### 6.1 「現在有効な最新版」の取得

通常のリスト表示や統計で使用。二重フィルタリングで確実に有効な許可のみ取得する。

**許可:**
```sql
WHERE 有効終了日時 IS NULL
  AND 廃止日 IS NULL
  AND 取消日 IS NULL
```

**施設:**
```sql
WHERE 有効終了日時 IS NULL
  AND 廃止年月日 IS NULL
```

二重フィルタリングの理由:
- `有効終了日時 IS NULL`: 更新による旧版、および廃止・取消済みレコードを除外
- `廃止日/取消日 IS NULL`: 万が一の不整合（有効終了日時の設定漏れ等）に対する防御

### 6.2 「特定時点での最新版」の取得（as-of検索）

許可検索画面の基準日指定で使用。

```sql
WHERE 有効開始日時 <= #基準日#
  AND (有効終了日時 IS NULL OR 有効終了日時 > #基準日#)
```

これにより:
- みなし有効期間中（14条3項）の許可も正しくヒットする
- 基準日時点で既に廃止・取消された許可は除外される（有効終了日時が設定済みのため）
- 基準日時点でまだ存在しない許可は除外される（有効開始日時が未来のため）

### 6.3 「同一許可の全バージョン」の取得（履歴表示）

許可履歴画面で使用。有効終了日時・廃止日のフィルタは**付けない**。

```sql
WHERE 許可論理ID = [対象の論理ID]
ORDER BY 有効開始日時 DESC
```

## 7. 状態遷移まとめ

### 7.1 業許可の状態

```
新規登録 ──→ 有効（有効終了日時=NULL, 廃止日=NULL, 取消日=NULL）
  │
  ├── 更新 ──→ 旧版（有効終了日時=設定済み）＋ 新版（有効、同一論理ID）
  ├── 廃止 ──→ 廃止済み（有効終了日時=設定済み, 廃止日=設定済み）
  ├── 取消 ──→ 取消済み（有効終了日時=設定済み, 取消日=設定済み）
  └── 復活 ──→ 有効に戻る（有効終了日時=NULL, 廃止日=NULL, 取消日=NULL）
```

### 7.2 施設の状態

```
新規登録 ──→ 有効（有効終了日時=NULL, 廃止年月日=NULL）
  │
  └── 廃止 ──→ 廃止済み（有効終了日時=設定済み, 廃止年月日=設定済み）
```

### 7.3 許可レコードの判定ロジック

```
有効終了日時が設定済み:
  取消日が設定済み   → 「取消」（行政処分）
  廃止日が設定済み   → 「廃止」（自主廃止）
  上記いずれもなし   → 「旧版」（更新により新版に置き換えられた）
有効終了日時がNULL:
  → 「有効」（現在有効な最新版）
```
